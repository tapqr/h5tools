# 账号与会话

这个站**公网可达**，登录是唯一的门。术语表里的每一条都与「这扇门怎么才不会被推开」有关。

## Language

**会话（session）**：
服务端持有、存在 Redis 里的登录状态，浏览器只拿到一个随机 id。
_Avoid_: token、JWT —— 这个项目不用 JWT，说成 token 会让人以为状态在客户端。

**默认拒绝**：
全局 AuthGuard 对**所有**路由要求已登录，放行必须显式 `@Public()`。
这不是"给接口加鉴权"，方向是反的：接口天生就有鉴权，要费力气才能取消。
_Avoid_: 鉴权中间件、加权限 —— 这些说法暗示"默认开放，逐个加锁"。

**初始口令**：
seed 建出来的 `admin` / `123123`，数据库里 `passwordChangedAt` 为 `null`。
生产环境带着它会**拒绝启动**。
_Avoid_: 默认密码 —— 叫"默认"容易让人觉得可以一直用下去。

**两个限流维度**：
登录失败同时按 **IP** 和**账号**计数，两边都要过。
只按 IP 挡不住换 IP 的撞库；只按账号则任何人都能拿错误密码把你锁在门外。
_Avoid_: 限流（单说） —— 不指明维度时这个词没有信息量。

**key 前缀**：
所有 Redis key 的命名空间（生产 `h5tools:` / 本地 `h5tools-dev:` / 测试 `h5tools-test:`）。
Redis 是**共享实例**，前缀是我们与别的项目之间唯一的隔离。
_Avoid_: 库号、db —— 隔离不靠库号，那个今天空不空是会变的。

## 不做的事

**注册流程**：数据模型是多用户的（业务表都带 `userId`），交互是单用户的。
账号由 `npm run user:create` 建出来。要给同事开号再跑一次即可，不用动表结构。

**两步验证**：整套安全押在一个密码上，前提是那个密码由密码管理器生成。
收益不抵每天多输一次验证码的摩擦。这个取舍依赖上面那个前提 —— 前提变了要重新评估。
