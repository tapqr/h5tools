# 用服务端 session，不用 JWT

登录状态存 Redis，浏览器只拿一个随机 session id（httpOnly cookie）。

## 为什么

**可即时吊销。** 改密码时要能把该账号已有的会话全部踢掉 —— 否则"改了密码"
对一个已经登录的攻击者毫无影响。JWT 做这件事需要额外维护一张吊销名单，
那张名单本身就是一次服务端查询，JWT 的"无状态"优势当场归零。

**没有续期问题。** 不需要 refresh token、不需要处理 token 过期时的竞态。
30 天滑动过期在服务端就是一次 `EXPIRE`。

**注销是真注销。** 不是"前端把 token 删了但它还有效"。

Redis 本来就要有（天气模块的缓存和限流都用它），session 是顺带的，没有新增依赖。

## 代价

每个请求多一次 Redis 往返。对这个站的量级完全不是问题。

## 配套实现

Redis 里除了 `sess:<sid>` 还记一份 `user-sess:<userId>` 集合 ——
没有它就没法"清掉某个用户的全部会话"，上面第一条理由也就落不了地。
