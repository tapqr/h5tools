# 天气对比

把多个天气服务商对同一坐标的预报**并排展示**，让用户自己判断哪家更准。
产品不替用户选，只负责把差异摆清楚。

从 `weather-app` 搬迁而来（2026-09-22）。

## Language

### 数据可用性

同一个词在这里有三种截然不同的含义。**不要用「降级」这个笼统说法**，改用下面三个：

**数据源失败**：
某个数据源整体不可用，`ProviderResult.status` 为 `'error'`，只带一句固定的中文用户文案。
_Avoid_: 降级、挂了

**字段缺失**：
数据源可用，但某些字段取不到，`status` 仍是 `'ok'`，缺的字段为 `null` 或 `[]`。
**只要拿到任意一部分数据就算成功。**
_Avoid_: 降级、部分失败

**模拟回落**：
上游失败时返回编造的数据充当结果。本项目**不做这件事** ——
术语列在这里是为了在讨论中能一眼指认它，并与上面两者区分开。
_Avoid_: 降级、mock 兜底

### 分歧

**分歧**：
各数据源对同一时刻或同一天给出不同的预报。这是产品要呈现的**对象本身**，
不是要消除或评价的问题 —— 各家跑的是独立的预测系统，分歧是常态。
_Avoid_: 误差、偏差、不准 —— 这几个词都暗示存在一个已知的正确答案，
而这个产品的前提恰恰是不知道

**共识判定**：
把各维度的分歧归纳成一个整体结论（如"高度一致"/"存在明显分歧"）。
**本项目刻意不做**，理由见 [`adr/0002-no-consensus-verdict.md`](adr/0002-no-consensus-verdict.md)。
收到"要不要加个总结卡"这类想法时，先去读那份 ADR。

**一致性评级**：
给单一维度（如某一天的预报）打的档位标签。与"共识判定"是同一类东西，
**同样不做**，同一份 ADR。

### 皮肤与作用域

**昼夜基调（daypart）**：
`day` / `twilight` / `night` 三档，由本地时间决定，换掉整页配色。
它是**内容的一部分**（在表达"外面现在什么样"），不是界面外壳偏好 ——
所以不跟随 `prefers-color-scheme`，白天就该是亮的，哪怕系统开着深色模式。

**页面作用域**：
所有天气样式都限定在 `.weather-page` 下，`data-daypart` 写在页面根节点上。
_Avoid_: `:root`、全局样式 —— 搬迁时专门把它从 `:root` 降下来的，
详见下面「搬迁时改了什么」。

## 搬迁时改了什么（与 weather-app 的差异）

原项目是一个独立部署的单页应用，这四条是并入工具站后必须改的：

**一、样式作用域从 `:root` 降到 `.weather-page`。**
不只是 `data-daypart` 那几条 —— `*`、`body`、`#app`、`button`、`ul`、`p`
这些应用级全局规则也一并收了进来。这份 CSS 是全局注入且**永不卸载**的，
而天气页是懒加载路由：访问过一次，`body` 的渐变背景和 `#app` 的 520px 限宽
就会留在整个会话里，把导航页也变成一条窄列。
`tests/weather-css.spec.ts` 用一条结构性测试钉住了这件事。

**二、缓存与限流从进程内换到 Redis。**
原项目的部署文档写明"不要开 cluster 或多实例"，因为两者都是进程内状态。
换成 Redis 后那条约束解除。**双档 TTL 与「坐标四舍五入到 2 位小数」的缓存 key
原样保留** —— 后者是为了抵消 GPS 抖动，约 1.1km 一格。

**三、接口需要登录。** 全站 AuthGuard 默认拒绝，天气与 geo 都不是 `@Public()`。
前端每个请求必须带 `credentials: 'same-origin'`，漏了的症状是全部 401。

**四、类型进了 `@h5tools/shared`。**
原项目前端的 `types/weather.ts` 是后端 interfaces 的**手抄副本**，
它自己的文档里写着「改后端契约必须同步改前端类型，没有任何自动检查会提醒你」。
现在改一个字段名前后端会同时编译失败。

## 两个不变的设计要点

**降级是产品核心，不是异常处理。** 单个数据源失败不影响另一家展示 ——
前端把失败的那家渲染成灰色卡片，而不是整页报错。区分「数据源失败」与「字段缺失」两层语义。

**归一化后的契约是唯一对外形态。** 两家原始数据差异很大（单位、日期格式、
预报天数都不同），全部在各自的 Provider 内部抹平：单位统一为 °C / % / km/h，
日期统一为 `YYYY-MM-DD`。但**两家的逐日天数不同**（和风 7 天、彩云 3 天，免费版差异），
**前端不假设各列行数相等**。

## 申请凭据

- **和风天气**：[console.qweather.com](https://console.qweather.com) 注册开发者账号，
  创建项目并选免费订阅。拿到的是**控制台里显示的专属 API Host**
  （形如 `xxxxxxxx.re.qweatherapi.com`），**不是**官方文档示例里那个公共域名 ——
  用错了会请求失败。
- **彩云天气**：[platform.caiyunapp.com/regist](https://platform.caiyunapp.com/regist)
  注册开放平台账号，获取免费 Token。

三个凭据缺任意一个会**启动即失败**，不会带着空凭据跑起来 ——
否则 `https://${apiHost}/v7/weather/now` 会变成主机名是 `v7` 的 URL，
真实 API Key 照样被发出去，而运维分不清是"配置漏了"还是"第三方挂了"。

## 加一家数据源

三步，聚合逻辑本身不用改：
1. 在 `apps/api/src/weather/providers/` 加一个实现 `WeatherProvider` 接口的类
2. 注册进 `providers.module.ts`（**那个数组的顺序就是界面上各家的左右位置**）
3. 在前端 `ProviderCard.vue` 的标签映射里加一行中文名
