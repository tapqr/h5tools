# 「端」按设备类型判定，不按视口宽度

`meta.platforms` 声明每个页面适配哪些端；判定依据是 UA + `pointer: coarse`，
**判定函数的签名里没有视口宽度**。

## 为什么

若按视口宽度判，在 PC 上把浏览器窗口拖窄到 900px，仅-PC 的页面会**突然变成
「不支持，请用手机」**。那是纯粹的 bug 体验。

「配置页只支持 PC」的真实含义是「不想为它写手机样式」，不是「窗口必须够宽」。
窄窗口让它横向滚动就行。

视口宽度只负责另一件事：那些「两端都适配」的页面内部怎么排版（CSS 断点）。
**两个概念不共用一个判据。**

## 平板归 PC 侧

iPad 横屏有 1024px 宽，放得下 PC 布局；强行给它底部 tab 反而别扭。
识别上有两个坑：Android 平板的 UA 里**没有** `Mobile` 一词（正好借此与手机区分），
iPadOS 13+ 的 Safari 默认伪装成 Macintosh（只能靠触屏信号兜住）。

## 代价

多一份设备判定逻辑要维护，而 UA 嗅探永远不可能覆盖全部设备。
兜底策略是「拿不准就归 PC 侧」—— 宁可给大屏设备一个不够顺手的布局，
也不要把它塞进单列手机布局。
